2. Why are we using AWS Cognito?

Building authentication completely from scratch is notoriously difficult and risky. Instead of manually storing passwords and writing OTP delivery systems, we rely on AWS Cognito.

The Real-World Analogy

"Imagine Freel is a highly secure logistics office building. AWS Cognito is the building's security desk.

Users tell the frontend (the lobby greeter) they want to enter. The frontend asks the backend (the building manager) to coordinate. The backend checks with Cognito, which decides whether the person is allowed in, whether their email is verified, and whether they can reset their password."

The Technical Reality

Cognito natively handles the most difficult parts of identity management:

  • Secure user creation (Signup)
  • Email verification codes
  • Password reset flows
  • Token issuance and authentication

However, our Backend still exists to compute secure hashes and keep AWS credentials out of the public browser.

Safer Password Handling

We don't want the liability of storing hashed passwords ourselves immediately.

Faster MVP Delivery

Allows backend to focus on core platform logic while Cognito handles identity.

Scalable Foundation

Provides enterprise-grade scalability and security natively.

3. Who is responsible for what?

To keep the platform secure, responsibilities are strictly separated.

🖥️ React Frontend

  • Showing forms & collecting input
  • Calling backend APIs
  • Showing success/error UI
  • Storing returned tokens
  • Route guards & redirecting

⚙️ Go Backend

  • Receiving auth requests
  • Validating request payloads
  • Computing the SecretHash
  • Calling Cognito via AWS SDK
  • Keeping Cognito credentials secure

☁️ AWS Cognito

  • Creating users
  • Email verification processing
  • Login authentication
  • Forgot/Reset password OTPs
  • Token generation

5. What is the SecretHash?

Our Cognito setup has an "App Client Secret", which prevents unauthorized apps from manipulating our users.

The Analogy

"Think of SecretHash as a wax seal that the backend stamps onto every request. When Cognito sees the wax seal, it trusts that the request is legitimately coming from our trusted backend server."

The Technical Reason

The client secret must never be exposed in the browser. Therefore, the frontend cannot talk to Cognito directly.

Instead, the frontend calls the Go backend. The backend uses the secret to safely compute the SecretHash, and sends it along to Cognito.

Important:

This is the primary reason the frontend does not talk directly to Cognito in our current architecture. The backend acts as a secure cryptographic middleman.

7. Signup & Email Verification Workflow

When a user registers, their account is created but marked as unconfirmed. They must verify their email before they can ever log in.

Signup Sequence
sequenceDiagram participant U as User participant F as React Frontend participant B as Go Backend participant C as AWS Cognito U->>F: Fills Signup Form F->>B: POST /auth/signup B->>B: Compute SecretHash B->>C: Call SignUp C-->>B: Unconfirmed User Created C->>U: Sends Verification Code B-->>F: Success Response F->>U: Redirect to Verify Email U->>F: Enters Code (OTP) F->>B: POST /auth/verify-email B->>C: Call ConfirmSignUp C-->>B: User Confirmed B-->>F: Success Response F->>U: Redirect to Login Page
1

User submits full name, company, email, and password on the frontend.

2

Backend computes the SecretHash and forwards the data to Cognito.

3

Cognito creates an unconfirmed user and emails them a verification code.

4

User enters the code on the Verify Email page.

5

Account is confirmed, and user is redirected to Login. They are not auto-logged in.

8. Login Workflow

Logging in exchanges credentials for tokens. After login, the frontend intelligently decides where to route the user based on their onboarding status.

Login Sequence
sequenceDiagram participant U as User participant F as React Frontend participant B as Go Backend participant C as AWS Cognito U->>F: Enters Email & Password F->>B: POST /auth/login B->>B: Compute SecretHash B->>C: Call InitiateAuth (USER_PASSWORD_AUTH) C-->>B: Returns Tokens B-->>F: Returns Tokens F->>F: Store Tokens in localStorage F->>F: Check Onboarding State alt Onboarding Incomplete F->>U: Redirect to Onboarding else Onboarding Complete F->>U: Redirect to Dashboard end
1

User submits email and password.

2

Backend calls Cognito, which validates the password and returns security tokens.

3

Frontend receives tokens and stores them in localStorage.

4

Frontend checks local state: has this user completed onboarding?

5

User is routed to Onboarding (if new) or Dashboard (if returning).

9. Forgot / Reset Password Workflow

A secure two-step recovery flow managed almost entirely by Cognito's built-in mechanics.

Recovery Sequence
sequenceDiagram participant U as User participant F as React Frontend participant B as Go Backend participant C as AWS Cognito U->>F: Enters Email on Forgot Password F->>B: POST /auth/forgot-password B->>C: Call ForgotPassword C->>U: Emails Reset Code F->>U: Redirect to Reset Password U->>F: Enters Code + New Password F->>B: POST /auth/reset-password B->>C: Call ConfirmForgotPassword C-->>B: Password Updated F->>U: Redirect to Login
1

User enters their email to request a reset.

2

Backend triggers Cognito to email a secure recovery code.

3

User enters the code and their new password on the Reset page.

4

Cognito updates the password securely.

5

User is redirected to the login page to sign in with their new credentials.

10. Route Guards & Browser Storage

To ensure a smooth, secure experience, the frontend maintains a local session and enforces strict routing rules.

What is stored in localStorage

  • freel_access_token
  • freel_id_token
  • freel_refresh_token
  • freel_session_user
  • Onboarding completion state (tied to email)

What Route Guards do

  • Not logged in: Redirect to Login.
  • Logged in + Onboarding incomplete: Redirect to Onboarding.
  • Logged in + Onboarding complete: Allow access to Dashboard.
  • Already logged in: Hide public auth pages and auto-redirect inside.
App Boot Flow
flowchart TD Start[App Opens] --> Check(Check localStorage) Check -->|No Session| Public[Show Public / Login] Check -->|Session Exists| Restore[Restore User] Restore --> CheckOnboard(Check Onboarding) CheckOnboard -->|Incomplete| GoOnboard[Go to Onboarding] CheckOnboard -->|Complete| GoDash[Go to Dashboard]
Cross-Tab Behavior:

If a user logs out in one browser tab, the frontend clears localStorage. Because localStorage is shared, all other open tabs instantly detect this and redirect to the login screen, ensuring security.

12. Deployment Architecture

Our code runs in environments perfectly tailored for their specific workloads.

Environment Map
graph TD User(User Browser) subgraph Vercel [Vercel Environment] React[React Frontend] end subgraph Render [Render Environment] Go[Go Backend API] end subgraph AWS [AWS Cloud] Cognito[Cognito User Pool] end User <-->|HTTPS| React React <-->|HTTPS API| Go Go <-->|AWS SDK| Cognito

Vercel

Hosts the React frontend. Ultra-fast global CDN delivery. Uses environment variables to know where the backend lives.

Render

Hosts the Go backend. Securely stores our Cognito Client Secret and AWS region variables away from public eyes.

AWS Cognito

The heavy lifter. Runs in Amazon Web Services, managing the actual user pool and automated email dispatching.

13. What is still Phase 1 / MVP?

Our current architecture is robust and highly secure, but it is intentionally a Minimum Viable Product. We made smart, practical choices to ship quickly.

What's Already Strong

  • Full secure auth flows working natively
  • Strict frontend/backend separation of concerns
  • Cognito secure foundation established
  • Onboarding + dashboard route protection active

What Will Evolve Later

  • Onboarding state is in localStorage; eventually it moves to the database.
  • /auth/me is a placeholder; it will expand to return full user profiles.
  • Deeper session hardening (e.g., rotating refresh tokens securely).
  • Building the core logistics modules behind the protected wall!
